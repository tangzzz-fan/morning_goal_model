# 产品需求文档 (PRD) - 智能洞察版 v2.0

| 文档版本 | v2.0 |
| --- | --- |
| **项目名称** | 每日目标智能洞察系统 (Goal Insight System) |
| **产品状态** | 规划中 |
| **核心目标** | 利用端侧 AI 能力，将 v1.0 的“记账式”体验升级为“私人教练式”的反馈体验，通过数据洞察提升用户目标达成率。 |

---

## 1. 项目背景与价值主张

### 1.1 背景 (Context)

v1.0 版本已经解决了用户“记录每日目标”的基础需求，沉淀了大量文本数据。但目前数据处于“休眠”状态，用户无法感知记录带来的长期价值，难以形成闭环，导致长期留存率存在下降风险。

### 1.2 核心价值 (Value Proposition)

**从“我记了什么”进化为“我做得怎么样”。**
通过 MobileBERT 和端侧数据分析算法，挖掘用户碎片化记录背后的**时间规律**、**隐性情绪**和**精力分布**，帮助用户优化时间管理和心理状态。

### 1.3 v2.0 范围界定 (Scope)

* **新增：** 端侧 NLP 解析引擎（MobileBERT）。
* **新增：** 本地数据洞察中心（Dashboard）。
* **新增：** 隐性情绪与行为模式识别算法。
* **维持：** 数据不出端（Privacy First），所有计算在本地完成。

---

## 2. 核心功能需求 (Functional Requirements)

### 2.1 功能模块一：智能语义解析层 (The Parser)

**目标：** 将用户输入的非结构化“碎碎念”转化为结构化数据，存入本地数据库。

| ID | 功能点 | 详细描述 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| **F1.1** | **意图与类别自动识别** | 用户输入文本后，后台静默调用 MobileBERT 进行多标签分类（如：工作、学习、生活、健康、社交）。 | 1. 准确率 > 85%。<br>

<br>2. 支持一条记录对应多个标签（如“跑步听书”=健康+学习）。 | P0 |
| **F1.2** | **隐性情绪计算** | 基于 BERT Embedding 和文本特征（标点、句长、否定词），计算每条记录的 `Sentiment Score` (-1.0 到 1.0) 和 `Energy Level` (0 到 10)。 | 1. 即使无显性情绪词，也能识别出“短句+负面词”为低落。 | P0 |
| **F1.3** | **实体抽取 (NER)** | 提取文本中的“时长”、“具体事项实体”。 | 1. 识别“2小时”、“30分钟”并标准化为分钟数。 | P1 |

### 2.2 功能模块二：数据洞察引擎 (The Insight Engine)

**目标：** 基于 F1 产生的结构化数据，进行多维度的交叉分析，寻找规律。

| ID | 功能点 | 详细描述 | 算法逻辑 (简述) | 优先级 |
| --- | --- | --- | --- | --- |
| **F2.1** | **生活重心热力聚类** | 识别用户一段时间内真正关注的“主题”，而非简单的分类统计。 | **K-Means 聚类：** 对过去 30 天的 Text Embedding 进行聚类，发现“Debug”、“写作”、“带娃”等高频语义簇。 | P0 |
| **F2.2** | **黄金时间段识别** | 分析用户在哪个时间段产出最高、情绪最好。 | **环形统计 + 关联分析：** 关联 `Timestamp` 和 `Sentiment Score`，找出情绪均值最高的时间窗口。 | P1 |
| **F2.3** | **倦怠预警 (Burnout Alert)** | 检测用户是否进入疲劳期或低效期。 | **趋势分析：** 检测连续 5 天 `Text Length` 下降 或 `Sentiment` 呈负向趋势。 | P1 |
| **F2.4** | **隐性习惯关联** | 发现用户未察觉的因果关系。 | **Apriori 规则：** 挖掘如“每次记录【会议】，情绪分值均低于 -0.5”的强关联规则。 | P2 |

### 2.3 功能模块三：洞察可视化前端 (The Dashboard)

**目标：** 将枯燥的数据分析结果，转化为用户看得懂、有体感的卡片。

#### 页面 A：周/月度回顾报告 (Weekly/Monthly Review)

* **精力饼图 (Energy Pie):** 基于 F1.1 的分类，展示时间/精力去向。
* *文案示例：* “本周你 60% 的精力花在了【创造性工作】上。”


* **心流曲线 (Flow Chart):** 基于 F1.2 的情绪分 + F1.3 的时长，绘制一周的情绪/效能波动曲线。
* *交互：* 点击曲线波峰，展示当时记录的那句话（高光时刻）。


* **聚类气泡 (Focus Bubbles):** 基于 F2.1，用气泡云展示本周核心关键词。
* *视觉：* 气泡大小代表提及频次/投入程度。



#### 页面 B：即时洞察卡片 (Smart Tips)

* **位置：** 首页顶部或输入框下方。
* **触发机制：** 当 F2.3 或 F2.4 命中特定阈值时出现。
* **样式：**
* *“发现你最近在深夜 23:00 后记录频率变高，且情绪偏焦虑，建议调整作息。”*
* *“恭喜！这是你连续第 5 天在‘阅读’上投入时间。”*

## 3. 非功能性需求 (Non-functional Requirements)

### 3.1 性能要求 (Performance)

* **推理延迟：** 用户输入完成后，NLP 解析（F1.1 ~ F1.3）应在后台异步执行，不得阻塞 UI 主线程。单次推理耗时应控制在 **200ms** 以内（基于 NPU/GPU 加速）。
* **电量控制：** 批量数据分析（F2 模块）应仅在**应用启动时**或**设备充电且闲置时**运行，避免后台偷跑电量。
* **App 体积：** 模型文件（MobileBERT 量化版）需控制在 **40MB** 以内，建议通过 On-demand Resources (ODR) 动态下发。

### 3.2 隐私与安全 (Privacy)

* **本地化原则：** 所有的模型推理、向量存储、统计分析**必须**在端侧（On-device）完成。禁止上传用户日志到云端。
* **数据擦除：** 用户删除某条日记时，对应的 Embedding 向量和统计缓存必须同步物理删除。

## 4. 数据埋点与成功指标 (Metrics)

由于保护隐私，我们不采集具体内容，但需采集**功能使用情况**来验证 v2.0 的成功：

* **核心指标 (North Star Metric):**
* **洞察卡片点击率 (CTR):** 用户点击/展开“周报”或“智能提示”的比例。
* **记录留存率 (Retention):** 开启智能洞察功能的用户，第 30 天的留存率是否高于 v1.0 用户。


* **辅助指标:**
* **标签修正率:** 用户手动修改 AI 自动生成的标签的比例（用于评估模型准确度，越低越好）。

## 5. 开发分期规划 (Roadmap)

* **Phase 2.1 (MVP):** 上线 MobileBERT 基础分类与实体提取，实现“自动打标签”和“基础饼图”。
* **Phase 2.2 (Intelligence):** 上线向量存储与聚类分析，推出“周度回顾报告”和“高光时刻”。
* **Phase 2.3 (Pro):** 上线情绪趋势分析与倦怠预警，完善“智能建议”系统。
